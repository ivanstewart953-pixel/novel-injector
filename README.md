# Novel Injector（小说注入器）

一个帮你在 SillyTavern（酒馆）里**"读完"一部长篇小说**、并让 AI 续写时**记得住原著**的插件。

> 想象一下：你让 AI 接着一本小说的剧情往下写，AI 却总忘记前面发生了什么、谁是谁、这个世界是什么样——这个插件就是来治这个毛病的。

📘 想知道每一步都改了什么？看 [完整更新记录](./更新记录.md)

---

## 一、这插件到底是干嘛的？🎯

**一句话：它替 AI 先把小说读了一遍，然后在你聊天时按需把相关内容喂给 AI。**

具体分三步：

1. **你上传小说** —— 支持 `.txt` 和部分 `.mobi` 格式；
2. **插件读小说** —— 调用 AI 把小说压缩成精华，整理出**剧情**、**角色**、**世界观**、**文风**这几类资料；
3. **聊天时注入** —— 你正常和 AI 聊天，插件会挑出当前用得上的资料，悄悄塞进 AI 的上下文里。

⚠️ 注意：它**不会逼 AI 照抄原著**。原著只是"参考书"，你自己改剧情、改人物关系都行，AI 会顺着你的改变走。

## 二、怎么安装？🛠️

**方法一：插件市场一键装（推荐）**

打开 SillyTavern 的第三方扩展安装入口，粘贴下面这行地址，点安装：

```
https://github.com/ZZZa-o/novel-injector
```

装完**刷新页面**，点顶部的📖书本图标就能打开插件面板。

**方法二：手动装**

把整个仓库文件夹放进酒馆的扩展目录：

```
SillyTavern/public/scripts/extensions/third-party/novel-injector
```

文件夹里应该有这些文件：

```
manifest.json
index.js
template.html
style.css
lib/
README.md
```

放好后刷新或重启酒馆，点顶部书本图标打开。

## 三、怎么开始用？9 步走 🚀

1. 进 **处理** 页，上传你的小说（`.txt` 或 `.mobi`）。
2. 填好 AI 接口信息（接口地址、Key、模型）。这个 AI 负责"读小说"，是**必需**的。
3. 点 **开始全自动清洗**。AI 开始一段一段读小说，把它压缩成精华。
4. 至少读完一段后，去 **剧情** 页看看——时间轴、主线、支线、转折点都在这。
5. 在剧情页点 **划分阶段**，把小说切成一段一段（比如"第一卷""第二卷"），后面好按段开关。
6. 想用"按意思搜原文"的话，去处理页把某个阶段 **向量化**（等于给这阶段内容建个"搜索索引"）。
7. 去 **阶段** 页，打开想给 AI 参考的阶段。
8. 回到聊天窗口，正常发消息就行，AI 会自己用上这些资料。
9. 想玩 **穿书**，去剧情页开穿书模式，状态栏里就能管理剧情进度。

> 💡 不向量化也能用。没向量化的阶段，AI 会直接读剧情原文，只是不如向量化"精准"，但省事。

## 四、5 个页面分别是干嘛的？📱

插件底部有 5 个页签：

| 页签 | 管什么 |
|---|---|
| **处理** | 上传小说、读小说（清洗）、生成文风、向量化、注入参数 |
| **剧情** | 偏差分析、穿书、世界观、剧情节点、阶段划分 |
| **角色** | 用户代入、角色人设、开关角色、AI 更新人设 |
| **阶段** | 开关阶段、生成阶段概括、角色演绎提示词 |
| **设置** | 插件总开关、全局提示词、外观配色、小说库、导入导出、清理 |

下面把每页的重要功能用大白话讲清楚。

### 处理页

**清洗（读小说）**
把每段小说变成两样东西：
- **压缩正文** —— 按时间顺序保留关键剧情、人物关系、时间地点、因果和转折；
- **角色/剧情清单** —— 这段里登场了谁、发生了什么事。

清洗可以暂停、可以续跑、单个段落失败了也能单独重读。已经读好的部分不会因为调大分段大小就白读。

**API 设置（喂给插件的 AI）**
- **清洗 API**（必需）：负责读小说、整理剧情角色、生成世界观和文风。
- **向量 API**（可选）：负责把阶段内容做成"搜索索引"。

支持设置超时、并发数、每分钟最多请求几次，防止把接口打爆。

**文风**
想学某本书的说话味道？三种办法：从原文自动截一段、自己粘贴一段范文、或指定某一章当样本。生成后会自动注入给 AI，不想用了清空就行。

**向量化**
把读好的阶段内容切成小块，用向量 API 做成索引存到浏览器里。做完之后，AI 能"按意思"找到相关原文，而不是瞎猜。

### 剧情页

**剧情偏差分析**
对比"你现在聊到哪了"和"原著写到哪了"，看看偏离了多少，把"已经发生的新事实"记下来，防止 AI 后面又照着原著硬来。例如角色已经死了、身份已经暴露，这些新事实会被记住，AI 不会当没发生。

**穿书模式**
适合"我穿进这本书"的玩法。围绕当前剧情节点管理进度：
- 勾选"这个节点已经推进完了"，读完的就归档；
- 可以**推演后文**，让 AI 给三个方向，点一下就能填进输入框；
- 可以**暂停**，暂停时不会继续推进剧情；
- 开启"沉浸"开关后，AI 只写 `<user>` 该知道的、被告知过的信息，不提前剧透秘密和身份。

**世界设定**
把世界观（国家、门派、势力、法则……）分门别类整理好，可以手动写、让 AI 生成、单类重新生成，每类都能单独开关注入。

**关键剧情**
剧情节点的四个视图：**时间轴 / 主线 / 支线 / 关键转折**。支持添加、编辑、删除、拖拽排序、修补支线关联。列表多了会自动分页，手机上也顺手。

### 角色页

**用户代入角色**
想"我扮演的就是原著里的某个角色"？打开这个功能，选一个角色，插件就会在发给 AI 的资料里，把 TA 的名字替换成 `<user>`，AI 就明白"这是玩家自己"，而不是一个 NPC。

- 称呼候选来自清洗时收集的别名（外号、称呼、身份称谓）；
- 称呼按出现阶段显示（一阶段、二阶段……）；
- 可以手动添加、编辑、删除称呼；
- **每个聊天独立保存**配置，换聊天互不影响；
- 只改注入层，**不改你的小说原文和向量数据**。

**角色人设**
角色按"主角 / 配角 / 反派 / 其他"分类展示。可以：
- 单个或整类开关注入；
- 看原始人设（清洗出的）和 AI 更新人设（AI 根据最近对话补的）；
- 手动加角色、删角色、改资料；
- 一键用 AI 批量更新人设；
- **自动休眠**：换阶段时，自动关掉这个阶段没出场的角色，主角和代入角色会保留。

> 角色多了会自动分页，每页 20 个起，可调。超过 5 个角色或真的翻页了才显示翻页栏。

### 阶段页

把小说切成阶段后，在这里控制**哪些阶段给 AI 看**：
- 单个开/关，或全部开/全部关；
- 生成阶段标题和概括；
- 编辑"角色演绎提示词"（让 AI 在这个阶段用指定的风格演角色）；
- 看到每个阶段有没有向量化。

没向量化的阶段，有两种喂法：
| 模式 | 说明 |
|---|---|
| **剧情节点** | 喂主线/支线/转折的要点，省 token |
| **压缩原文** | 喂这阶段的原文精华，信息全但更费 token |

同时开的阶段太多、塞不下时，插件会优先保当前阶段，其余的退化成"阶段概括"，再放不下就跳过，并在页面告诉你这轮到底喂了多少。

### 设置页

**插件总开关**
一键关掉所有注入。重新打开时，之前的穿书状态会自动恢复。

**全局提示词**
三种模式：不用 / 跟着酒馆预设走 / 用插件内置的两条提示词。跟着预设走时，插件会明确标记"这是后台整理任务，不是角色扮演"，尽量不打扰你当前的角色卡。

**外观配色**
换个皮肤！主色、次色、强调、警示、背景、文字色都能调，用取色器或直接输入 `#RRGGBB` 都行。内置主题：默认、"星糖梦簿"、"星糖梦簿·夜间"。可导入导出、新建、删除、保存自己的主题。
还能开 **跟随美化**（颜色跟着酒馆美化主题走）和 **去除边框**（界面更简洁）。

**小说库**
当前进度可以存成"快照"，一本小说存一个。支持保存、加载、更新、重命名、删除。换电脑或换设备，用 ZIP 导出一份带走。

**导入导出**
- **导出 ZIP**：包含设置和小说数据，**不含**你的 API 地址、Key、模型——放心分享；
- **导入**：支持新格式 ZIP 和旧格式 JSON。导入不会覆盖你现在的小说，会作为新快照加进来，手动加载才会切换。

**清理**
- 清当前小说向量缓存；
- 清全部数据（会二次确认，别怕点错）。

## 五、几个常问的问题 ❓

**不向量化能用吗？**
能。没向量化的阶段直接喂剧情原文，只是没向量化"精准"。

**改完阶段要不要重新向量化？**
要。阶段划分变了，受影响阶段的向量索引会重置，重新选上再向量化一次即可。

**为什么用户代入里没有自动出现很多称呼？**
称呼来自清洗时收集的"角色别名"。旧的小说是用老版本读的、没收集到，重新清洗相关段落就会有了。手动添加的称呼马上能用。

**用户代入会影响向量召回吗？**
不影响。替换只发生在注入层，小说原文、剧情、角色、向量全都不动。

**穿书模式在哪？**
剧情页，"世界设定"上面。正文里的进度条/小窗由穿书设置里的显示方式控制。

**导入备份会把我现在的小说覆盖掉吗？**
不会。导入只会新增一本快照，手动加载才切换。

**导出会泄露我的 API 配置吗？**
不会，导出文件里不含接口地址、模型和 Key。

**清洗老失败怎么办？**
先检查接口地址、Key、模型、超时和限速。单段失败可以单独重读那一小段，也可以点"重试失败分段"。

**AI 人设更新了，页面却没显示？**
多半是模型返回被截断了（`finish_reason: length`），半截的 JSON 插件不会存。插件会自动重试 3 次，还失败就弹窗告诉你哪个人物、为啥失败。

**向量化失败怎么办？**
检查向量 API 的地址、Key、模型名。被限速就降低每分钟请求数再试。可以用"向量诊断"看浏览器里实际存了啥。

## 六、数据都存哪？🗂️

| 数据 | 存哪 |
|---|---|
| 设置、API 配置、小说库索引、阶段开关 | 酒馆的 `extension_settings` |
| 剧情、角色、称呼、清洗状态、文风 | 酒馆 `user/files` 下的 `*_core.json` |
| 清洗压缩正文 | 酒馆 `user/files` 下的 `*_chunks.json` |
| 持久化阶段索引 | 酒馆 `user/files` 下的 `*_stages.json` |
| 向量索引 | 浏览器 IndexedDB（库名 `NovelInjectorVectors`） |
| 穿书进度 | 当前聊天第一条消息上 |
| 用户代入配置 | 当前聊天的 `chat_metadata` |

服务端重数据文件用拼音命名，例如 `ni_<快照名拼音>_<随机key>_core.json`。

## 七、兼容性说明 🔧

- 插件是 SillyTavern 的**第三方扩展**，需要酒馆环境；
- 清洗 / 向量 API 用的是 **OpenAI 兼容**格式；
- 向量数据存在浏览器的 **IndexedDB** 里；
- 如果酒馆的扩展提示词接口大改，注入位置和深度可能需要跟着调。
